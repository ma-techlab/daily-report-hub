# 店舗日報ハブ 操作手順書

この手順書は、初めて日報を入力する店舗担当者と、確認・集計を行う管理者向けです。
実装済みの Google フォーム、スプレッドシート、メール通知だけを対象にしています。

## 最初に知っておくこと

- 店舗担当者が使うのは「店舗日報」Google フォームです。スプレッドシートの Google フォーム自動作成タブではなく、整形後の正式データは「日報」タブで確認します。
- メールは `DRY_RUN=false` にするまで実送信されません。試験中は `DRY_RUN=true` のまま「送信ログ」を確認します。
- フォームの送信完了画面は「日報」への受付成功を保証しません。管理者は「受付エラー」も確認します。

## 店舗担当者：毎日の入力

1. 管理者から共有された「店舗日報」フォームを開きます。
2. 自店舗と営業日を選びます。
3. 予定食数、提供食数、残食数、出勤人数を0以上の整数で入力します。残食数は提供食数以下にします。
4. 衛生点検を「すべて実施」または「未実施の項目あり」から選びます。
5. 本部への相談を「なし」または「あり」から選びます。相談内容や引き継ぎは「連絡事項」に入力します。
6. 入力内容を確認し、送信します。

同じ店舗・同じ営業日を送り直すと、新しい行は増えず「日報」の同じ行が上書きされ、修正回数が1増えます。
修正後も要対応に該当する場合は「修正」と付いた要対応通知の対象です。修正によって要対応が解消した場合、日報の理由は消えますが、取消メールは送られません。

## 要対応と判定される条件

次のどれかに該当すると、「日報」の「要対応の理由」に理由が入り、本部宛ての通知対象になります。

- 衛生点検に未実施の項目がある
- 本部への相談がある
- `残食数 ÷ 提供食数` が設定した残食率の基準を超える
- `(予定食数 - 提供食数) ÷ 予定食数` が設定した提供不足率の基準を超える

基準と同じ値は通知対象ではなく、超えた場合だけが対象です。提供食数が0の場合、残食率は0%として扱います。

## 管理者：毎日の確認

- 「日報」：店舗別の入力、残食率、要対応の理由、受信日時、修正回数を確認します。
- 「受付エラー」：受付けなかった回答と理由を確認し、店舗に再入力を依頼します。
- 「送信ログ」：要対応、リマインド、週次まとめの状態を確認します。状態は「送信」、「DRY_RUN（未送信）」、「宛先なしのため未送信」、「送信上限に近いため未送信」、「失敗：…」のいずれかです。
- 自動リマインドは、店舗マスタで有効かつ定休日でない店舗のうち、当日分が未提出の店舗に送られます。

すぐ確認する場合は、スプレッドシートの「日報ハブ」メニューから「いま未提出の店舗を確認（リマインド）」を実行します。この操作は確認だけではなく、メール設定に従って送信または送信ログへの記録を行います。

## 管理者：週次まとめ

毎週月曜日に前週の月曜日〜日曜日を店舗別に集計します。「週次集計」に営業日数、提出数、提出率、提供食数、残食率、要対応件数が記録され、本部に同内容のメールが通知されます。

- 提出率の分母は、店舗マスタの定休日を除いた営業日数です。
- 定休日の日付で送信された日報は「日報」に保存されますが、週次の提出数、提供食数、残食率、要対応件数には含まれません。臨時営業日は現行機能で自動判定できないため、週次集計前に定休曜日の設定を確認します。
- 残食率は、週の残食数合計を提供食数合計で割った値です。
- 同じ週を作り直すと、その週の行を置き換えるため重複しません。
- 手動で作るときは、「日報ハブ」→「前週のまとめを作成」を実行します。

## 店舗マスタを変更するとき

「店舗マスタ」の店舗名、責任者メール、定休曜日、有効を変更した後、「日報ハブ」→「フォームの店舗を更新」を実行します。定休曜日は `土,日` のように入力します。有効な店舗だけがフォームの選択肢に入ります。

- 運用開始後の店舗IDは、過去の日報とのひも付けに使うため変更しません。
- 店舗IDまたは店舗名が空、または重複している場合、初期設定とフォーム更新は停止して理由を表示します。
- 有効な店舗が0件の場合もフォームは更新されません。

日報や週次集計のキー列・数式相当の値を直接書き換えると、上書き判定や集計が正しくできなくなるため、修正は原則としてフォームから送り直します。
